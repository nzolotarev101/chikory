# Friction Report: F-180 — Plan Meta-Judge Gate Halts Chain on Imperfect LLM DAG Decomposition

- **Friction ID**: `F-180`
- **Class**: `product`
- **Component**: `packages/sdk-ts` (Chain Orchestrator & Plan Meta-Judge Gate)
- **First Observed**: `dogfood-120` (`devbox run chain-dogfood`)

## Summary

When `chikory chain` decomposes a high-level goal into a multi-node Directed Acyclic Graph (DAG), the **Plan Meta-Judge Gate** audits the generated node graph for structural coherence, literal constraint retention, and execution dependency rules.

If the zero-shot planner LLM generates a slightly imperfect DAG (e.g. dropping mandated literal requirement strings or omitting explicit node-level serialization dependencies), the meta-judge gate immediately halts the chain (`REJECTED`) and exits. 

Rather than entering an automated **plan self-healing / re-prompting loop** (where the judge feeds the specific rejection feedback back to the planner to generate an adjusted DAG), the workflow requires the human operator to manually refine prompt hints or re-launch.

## System Impact

- **Operational Friction**: Requires manual intervention and prompt hint authoring in spec YAMLs when zero-shot decomposition drops mandated goal literals.
- **Product Gap**: Durable chain execution should natively feature a plan repair/self-heal loop for DAG decomposition, mirroring the per-node execution self-heal capabilities.
