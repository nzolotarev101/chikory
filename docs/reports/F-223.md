# Friction Report: F-223 … F-226 — the plan gate chased backticked words in a circle for $0.7764

- **Friction IDs**: `F-223` (the repair brief truncates away its own instruction) ·
  `F-224` (the literal floor searches less than the node receives) · `F-225` (every
  backtick in the goal is a hard mandate) · `F-226` (the repair loop cannot tell
  oscillation from progress)
- **Class**: `product`
- **Component**: `packages/sdk-ts` (`src/heal/gate-repair.ts`,
  `src/planner/literal-preservation.ts`, `src/planner/plan-repair.ts`, `src/cli/chain.ts`)
  and the launch preflight (`scripts/dogfood-progression.sh`, `scripts/dogfood.sh`)
- **First Observed**: `dogfood-121` launch attempt, 2026-07-30 — the plan meta-judge gate
  (the pre-execution check on a decomposition) stopped the chain before any node ran
- **Fixed**: 2026-07-30 session, hand-landed as **WP-549** (F-223), **WP-550**
  (F-224 + F-225), **WP-551** (F-226)
- **Status**: **CLOSED** — every fix proven RED-first against the real artifacts
  (dogfood-120's persisted plan and dogfood-121's real goal), 1176 sdk-ts tests green

## Plain summary

The launch never started. `devbox run chain-dogfood` spent **$0.7764 across four planning
attempts** and quit, and nothing was journaled — no chain database exists, so the only
record was the terminal output. Attempt 1 caught a real defect in how the plan assigned
its acceptance criteria. Attempts 2–4 did nothing but chase backticked words: each one
fixed the word it was told about and dropped a different one, including one it had
already fixed two attempts earlier.

The trigger is the WP-257 literal floor (the guard that stops a planner paraphrasing a
mandated identifier away, from F-64). The reason it could not recover is the repair
loop's own plumbing.

## The evidence

The whole trail, from the launch output:

| attempt | $ | rejected for |
|---|---|---|
| 1 | 0.1638 | **real**: AC-1 attached to `N-3`/`N-4`, whose scopes do not exercise the comparison oracle; AC-5 unassigned |
| 2 | 0.2159 | mandated literal `rawResultsDir` and `devbox run` in no node goal |
| 3 | 0.2074 | mandated literal `benchmarks/` in no node goal |
| 4 | 0.1893 | mandated literal `any` — and **`devbox run` again** |

`devbox run` was satisfied at attempt 2 and lost again at attempt 4. That is churn, not
convergence: raising the attempt cap to 10 buys four more rounds of the same and fails
for ~$2.

### F-223 — the brief truncated away its own instruction

`buildGateRepairBrief` rendered header → defects → rationale → prior outline →
**instruction**, then clamped the WHOLE string at `GATE_REPAIR_BRIEF_MAX_CHARS = 2000`.

Measured against dogfood-120's persisted plan
(`.chikory/chains/chain-0723ac0b-…/chain.db`, `chain_entries` kind `plan`):

| part | chars |
|---|---|
| six node goals, as `planOutline` renders them | **3,798** |
| gate rationale (real REVISE) | 610 |
| machine-checked defects (2 literal gaps) | ~220 |
| **brief as rendered** | **~5,300** |
| **brief as delivered** | 2,000 |

So the planner read the header, the defects, the rationale, and roughly one node of
outline. It never reached *"Keep the parts of your plan it did not object to — node ids,
dependency order, and write sets that were accepted should survive unchanged."* Every
retry was structurally told to start over. That is the whack-a-mole, in one line.

### F-224 — the floor searched a narrower surface than the node receives

`planLiteralGaps` tested `node.goal` only. But `buildPlan`
(`planner/assemble.ts:44-52`) hydrates a covered criterion's description and executable
`check` **verbatim** from the goal spec — F-40's own rule. `rawResultsDir` was reported
missing while sitting verbatim in AC-1's and AC-4's checks. A false gap, twice paid for.

The token-boundary rule had the same shape of defect in reverse: `containsExactToken`
demanded a non-word character after the literal, so `benchmarks/tasks/` did **not**
satisfy `benchmarks/` — a *more specific* path failed to satisfy its own prefix.

### F-225 — every backtick in the goal became a hard requirement

dogfood-121's goal mandated **19 literals**. Alongside the real ones sat prose (`any`,
`check`, `command`, `git`, `npx`), a command form (`devbox run`), and narrative context
(`7ad4bd3`, `N-2`, `chain-0723ac0b-4eba-413a-933f-2d1646a4f643`, and `docs/reports/…` —
an ellipsis no plan can carry). Three of the four gaps that burned $0.62 were prose.

### F-226 — the loop could not see it was churning

`planAndGateChain` kept no gap history. Each brief named only what was missing *now*, so
the planner patched those and rewrote node goals that were already fine. Nothing compared
attempt 4's defects to attempt 2's, and nothing carried the standing contract forward.

## The fixes

| WP | Friction | Change | Proof |
|---|---|---|---|
| WP-549 | F-223 | The brief is **budgeted**, not clamped: header + defects + instruction are mandatory and reserved first; the outline is shrunk per ENTRY so every node id survives; the rationale takes what is left. Cap 2000 → 4000 (it rides a planner prompt, not a compacted step context). | `test/heal/gate-repair.test.ts` — 5 cases RED before the change, using the real 6-node outline |
| WP-550 | F-224 | A literal counts as preserved if it survives in the node's goal, its id, **or any of its acceptance criteria** — the surfaces `buildPlan` fills verbatim. A trailing-slash literal is satisfied by any path under it. | `test/planner/literal-preservation.test.ts` — `rawResultsDir` in an AC check is no gap; `benchmarks/tasks/` satisfies `benchmarks/`; `benchmarksX/` does not |
| WP-550 | F-225 | `isMandatedLiteral` — only repo-artifact shapes are mandated (paths, dotted/underscored/camelCase identifiers, flags, field assertions). Prose, elided fragments and opaque ids (SHAs, chain ids) are exempt. | same file — the real dogfood-121 goal keeps `rawResultsDir`/`benchmarks/`/`summary.json`/`base_verification_command`/`unverifiedTasks`, drops `any`/`devbox run`/`git`/`npx`/`check`/`command` |
| WP-551 | F-226 | `classifyGapProgress` / `returnedGaps`: a defect that returns after being satisfied stops the loop, naming it. `stalled` still repairs. The brief now carries the **full literal inventory** (`literal → carrier node`, or `MISSING`) in its own section, held apart from the defect list so a standing contract is never read as churn. | `test/heal/gate-repair.test.ts` replays dogfood-121's real trail: shrinking, shrinking, **oscillating** at attempt 4; `test/planner/plan-repair.test.ts` for the inventory |

The **F-64 teeth are unchanged**: a node goal that paraphrases a mandated identifier,
with no criterion carrying it, is still a gap. That case is pinned by its own test.

### Preflight: the author sees the mandate at $0

`scripts/dogfood-progression.sh --spec <yaml>` now prints the mandated set, the exempt
prose set, and a ⚠️ for every mandated literal carried by **no** acceptance criterion —
those are the ones the planner must recite, and therefore the ones that can churn.
`scripts/dogfood.sh` re-runs it (`--literals`) after the SDK rebuild, where `dist` is
guaranteed fresh. On dogfood-121: 16 mandated, 3 exempt, 8 prose-only. The harness cannot
tell a goal's narrative from its contract — but it can show the author, before a plan is
ever paid for.

| literal | outcome |
|---|---|
| `devbox run` | not mandated (prose) |
| `any` | not mandated (prose) |

All four literals that cost $0.62 are gone. The gaps that remain are genuine deliverable
paths no node goal names.

## Not fixed here, deliberately

- **The executor never sees the chain's overall goal.** `chainLink.planGoal` is rendered
  for the JUDGE only (`judge/prompt.ts:165`). That is *why* the literal floor is
  load-bearing for constraint prose: a node run sees its own goal and nothing else, so a
  constraint the planner leaves behind is a constraint the executor never receives. The
  planner prompt now asks for constraints to be restated by name, and the repo's own
  `CLAUDE.md`/`AGENTS.md` carry the tooling rules — but forwarding `planGoal` into the
  executor prompt (the WP-545 `ContextBundle.notes` pattern) is the durable fix. Queued.
- **A plan-gate stop journals nothing.** $0.7764 of real spend left no durable record —
  no chain database is created until the gate returns PROCEED, so the repair trail exists
  only in the terminal scrollback and cannot reach the ledger. Recorded, no WP opened.

## Verdict on the thesis

A gate that rejects an artifact for a defect it will not let the retry see is a gate that
converts *repairable* into *terminal*. WP-542 built the repair tier so a rejected plan
heals instead of ending the launch; F-223 shows the tier can be defeated by its own
formatting. The cost was small and entirely pre-execution — which is the tier working —
but four attempts producing no convergence is the signal to read, and the loop had no way
to read it. It does now.
